# FT-063 evidence: floats and `\includegraphics` vs pdfLaTeX

Narrow claim: on these 10 fixtures (12pt article, US Letter, 1in margins,
Latin Modern, `\parindent 0pt`), `flashtex-render` places every image box,
caption start and body-paragraph start on the same page as pdfLaTeX and
within 1 pt; measured maximum deviation 0.041 bp. No claim beyond these
fixtures, this class size and these float parameters.

## Provenance

| item | value |
| --- | --- |
| reference engine (oracle only) | pdfTeX 3.141592653-2.6-1.40.29 (TeX Live 2026), `/Library/TeX/texbin/pdflatex`, MacTeX on mac-m5pro-kabir, 2026-09-13 |
| probes | `fixtures/floats/oracle.py`: `\pdfsavepos` whatsits (zero size) around `\includegraphics` (after `\leavevmode`), inside `\@makecaption`'s box, and in `\everypar`; positions in sp converted to bp from the top-left |
| references | `fixtures/floats/reference/NN-*.json` (committed; cargo never runs TeX) |
| fixtures | `fixtures/floats/NN-*.tex`, images in `fixtures/floats/images/` (generated by `make_fixtures.py`; the JPEG was made once with macOS `sips` and committed) |
| gate | `cargo test --release --test floats_oracle` (`tests/floats_oracle.rs`), 1 pt tolerance, page numbers must match |

## Result (`cargo test --release --test floats_oracle -- --nocapture`)

| fixture | what it exercises | pages ours/ref | anchors checked | max abs diff (bp) |
|---|---|---|---|---|
| 01-here | `[h]` PNG (no pHYs, 72 dpi) placed in the text | 1/1 | 4 | 0.001 |
| 02-top | `[t]` PNG with pHYs 144 dpi, top of the current page | 1/1 | 4 | 0.001 |
| 03-bottom | `[b]`, `width=2in` | 1/1 | 4 | 0.041 |
| 04-default-tbp | no specifier (class `tbp`), JPEG `height=1.5in` | 1/1 | 4 | 0.001 |
| 05-here-overflow | `[h]` that does not fit: `h` → `ht`, deferred to the next page's top | 2/2 | 4 | 0.001 |
| 06-float-page | 520 bp image `[tbp]`: too tall for top/bottom, float page (`\@tryfcolumn`, vertically centred) | 3/3 | 4 | 0.001 |
| 07-top-number | three `[t]` figures: `topnumber`=2, third deferred to page 2 | 2/2 | 10 | 0.000 |
| 08-table-ref | `table` with caption above the image, `width=3cm,height=1cm`; PDF `scale=0.5`; `\ref` to both | 1/1 | 7 | 0.002 |
| 09-crop-keepaspect | PDF CropBox with `width,height,keepaspectratio`; `angle=90,height=1in` uncentred `[b]` | 1/1 | 7 | 0.015 |
| 10-mixed | multi-line (justified) caption, `0.4\textwidth`, `[h]` table with extension search, `[p]` flushed by `\end{document}` | 3/3 | 10 | 0.011 |

Anchors: every image box (x, top, width, height), every caption's first
glyph (x, baseline), every body paragraph's first glyph (x, baseline).

Also measured with the oracle: the committed JPEG (JFIF units 0 + EXIF 96 dpi)
is sized by pdfTeX at 72 dpi (`\wd` = 192.71951pt for 192 px), which
`graphics.rs` follows.

## Not covered (reported, not guessed)

- `\includegraphics` in running text (outside floats): compiler's existing
  unsupported warning.
- Text other than `\includegraphics`/`\caption`/`\label`/`\centering` inside a
  float (e.g. `tabular`): `float_content_unsupported`, omitted.
- `trim`/`clip`/`viewport`/`bb`/`origin`: `graphics_option`, ignored.
- PDFs whose page tree exists only in compressed object streams:
  `image_unavailable`.
- Two-column floats (`figure*` is treated as `figure`), `\clearpage` flushing
  floats mid-document, `\suppressfloats`, `\FloatBarrier`, `float`'s `[H]`.
- 10pt/11pt float skips come from `size10.clo`/`size11.clo` but have no
  fixture yet.
