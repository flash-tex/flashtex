maintainability and stability (no hand-adding symbols or commands one by one).

**REWRITE** replace a structure rather than extend it, with the justification
stated in place.

Where a number is measured it says so and names the command. Everything else
is a belief from reading the code.

Facts this establishes:

- **Macro expansion is 1–2 % of a cold compile** (0.3–0.8 ms on every
  real-world fixture, ~0.1 ms per KB of source on the synthetic cases). The
  belief that executing real package code is "too slow" is not supported by
  the current engine's cost per token; §3.4 gives the bound.
- **Cold first render is dominated by work outside the phases** (fonts):
  plain-article 29.3 ms total vs 5.3 ms of phases. On real documents the warm
  keystroke is 1.6–10 ms, i.e. unnoticeable; on 500 KB it is 189 ms, and
  adapt+typeset is where a 500 KB document spends its time (271 ms cold).
- **unicode-accents is a 335 ms outlier with all phases at ~2 ms.**
  `flashtex-render --timing` on the same fixture: `r1 rendered in 625.38 ms,
  r2 1.41 ms, r3 1.16 ms`, with diagnostics `font_face_substituted: C70/min
  … outlines painted from HiraMinProN-W3` — the first request builds the
  system font index (`font-discovery`) to find a CJK face; the perf-bench
  export scenario pays it again on every export (372 ms warm). §3.8.

Speed cost of running real code (belief, bounded by measurement): the engine
spends ~0.1 ms per KB of source; `parskip.sty` is 6 KB, `setspace.sty` 15 KB,
`geometry.sty` 40 KB, `amsmath.sty` 100 KB. Even the whole standard preamble
of a typical article (~300 KB of `.sty`/`.cls` text) is ~30 ms cold at today's
per-token cost, and **zero warm** once the engine state after the preamble is
snapshotted (§3.4): the kernel prelude is already cached once per thread
(`expand.rs:530` `thread_local! INITIAL`); the same mechanism extended to
"state after `\begin{document}`", keyed by the preamble bytes and the package
texts, removes the cost from every keystroke in the body. The per-document
`ExpansionCache` (`expansion.rs:1568`, LRU of 4) already invalidates on package
text changes.

### C. Duplication and inconsistency

1. **Class data lives in four crates** (table in A). Two `\@startsection`
   tables are both live on different construction paths (`Stylesheet::article`
   vs `class_geometry::sections::headings`); `document-style::list_level()`
   computes a `leftmargin` that the adapter ignores in favour of its own
   `article_leftmargin_em`; `class-geometry`'s footnote parameters are computed
   for every class and never read. A maintainer fixing a pdflatex mismatch in
   `compiler::layout` changes nothing the PDF shows.
2. **Vendoring** (§1.2). The stated reason — "so the visual-oracle harness can
   build from a `git archive` of this directory alone" — is a harness
   convenience that costs a re-pin per feature, a runbook
   (`docs/integration/repin-runbook.md`), a pin-integrity script nobody runs
   in CI, seven pin-survival features, and an inert-fix failure mode that has
   already happened (#840/#839/#836 TAB catcode; #936 provenance). `class-geometry`
   and `font-discovery` are already consumed live by path, proving the
   alternative works.
3. **Mac vs iPad**: the shared core is real symlinks (`FlashTeXProtocol` 6.5k
   LOC, `FlashTeXEditorCore` 2.0k). Genuine duplicates outside it: the syntax
   palette (`apps/mac/.../SyntaxHighlighter.swift:15–40` vs
   `apps/ios/FlashTeXPad/EditorTheme.swift:10–40`, hand-copied, no check);
   `apps/ios/FlashTeXPad/Resources/compile-result.json` mirrors
   `protocol/fixtures/compile-result.json` with no sync; `review-workflow.json`
   cites a crate deleted in `39118b9f0`.
4. **Tools re-deriving the same thing**: the pdflatex oracle wrapper is
   reimplemented in 6 places (`tools/kernel-math-gap/measure.py:116`,
   `tools/real-world-corpus/run.py:163`, `compiler/scripts/color_oracle.py`,
   `unicode-tex/tools/run_oracle.py`, `tex-text-encoding/tools/generate_oracle.py`,
   `font-resources/tools/run_boundary_oracle.py`, `math-layout/tools/oracle_compare.py`);
   TFM parsing in Python 4 times; `tools/visual-oracle/rank.py` correctly
   imports `real-world-corpus/run.py`.
5. **Second layout engine**: `compiler/src/layout.rs` (4,941) +
   `layout/footnotes.rs` (846) implement a v1 page layout with their own
   copies of all class data. The Mac app can still fall back to
   `flashtex-compiler` when `flashtex-render` is not bundled
   (`ShellModel.swift:745`), so it is not dead, but it is a second answer to
   every layout question.

### D. Stability risks

- **The perf-bench font-gate pattern** (`e015c066f`): a hand-maintained list
  (`fontgate.rs:52 TEXMF_METRIC_DIRS`) that must mirror `FontSet::tfm_dirs_for`,
  plus a gate that *warned* when a baseline case dropped out. Siblings of the
  same shape: `check-vendor-pins.sh` DRIFT is "reported, never fails";
  perf-bench `--only` exclusions still only warn (`src/tests.rs:155`).
- **Silent fallbacks in the glyph path**: `fonts.rs:1080` and `mathfont.rs:766`
  `advance(gid).unwrap_or(0)` (a missing glyph becomes zero width, no
  diagnostic); `typeset.rs:2854` `glyph_id(ch).unwrap_or(0)` paints `.notdef`;
  `pagebuild.rs:412` `eprintln!` page-break diagnostics never reach the wire;
  `pdf/src/compare.rs:575, 647` `unwrap_or_default()` makes a malformed
  reference PDF compare as "identical empty".
- **Generated tables without staleness gates** (table in A): every generator
  has a provenance header, none is re-run in CI or checked against a committed
  input manifest.
- **Tests that never run**: font-resources (9 `#[ignore]`/env-gated files) and
  document-runtime are outside the CI matrix entirely; `#24` records that the
  visual-oracle acceptance pins FlashTeX's own bytes, not pdflatex's.
- **Source-byte re-derivation** (34 sites in `adapter.rs`, 9 in `typeset.rs`
  mention it; `adapter.rs:1–11` documents it as policy): the meaning of a token
  is decided from `source[span]`. A token from a macro replacement carries the
  invocation span, so #760 lists three live "span width == 2" tests that fail
  in both directions, #949 drops a blank between macro arguments, and the
  `linebreak-skip` feature exists because `\\[-6pt]` inside a `\newcommand`
  was invisible to the byte scan. This is the mechanism by which every future
  `.sty` executed through the engine will produce wrong output.
- **`\ifhmode`/`\ifmmode`/`\ifvmode`** are primitives reading `self.st.mode`
  (`expand.rs:5248`), and `Engine::set_mode` has no caller in the repository:
  `\ifvmode` is always true. `\output` is a stored `Toks` register
  (`expand.rs:6649`) that nothing executes.
- **Debug/release output differs** (#667) — a digest gate that only runs in
  release cannot see it.

### E. Structural limits on priority 0

1. **No `\insert`/`\mark`/`\vsplit`/`\output` execution.** Floats
   (`floats.rs` + `typeset/floatpage.rs`), footnotes (`typeset/footnotes.rs`),
   `\marginpar`, `multicols` (`typeset/multicol.rs`, 2,235 LOC transcribing
   `multicol.sty`) and `longtable` (`longtable.rs`) are each a hand transcription
   riding on the non-generic `pagebuild.rs`; each module's header lists the
   combinations it cannot represent (float page + column float page,
   footnotes in minipages/captions/cells, multicols in twocolumn, floats with
   multicols, notes inside floats). #944 (beamer) and #743 (`\twocolumn`) are
   symptoms.
2. **Expansion finishes before layout starts**, in a different crate, so any
   macro whose meaning depends on typesetting state (`\ifhmode`, `\lastskip`,
   `\prevdepth`, `\wd` of a set box, `\pagetotal`) is wrong by construction.
3. **Floats, `multicols`, `tikzpicture` and `fontspec` commands are found by
   scanning raw bytes and blanked before the compiler parses**
   (`render-pipeline/src/lib.rs:224–240`), so the parser never sees them and
   they cannot come from a macro.
4. **Closed enums at the boundary** (`Block` 26 variants, `Inline` 34,
   `Nucleus` 23), matched at ~600 sites in the pipeline, plus a vendor re-pin
   per new variant.
5. **No expl3, no `\halign`, no `\parshape`**; TikZ is an original interpreter
   of a subset (`vector-graphics/src/tikz`, 4.5k LOC; no `\pic`/`\matrix`/
   `plot`/decorations, no pgfplots); `fontspec` is a byte-scanned effect model
   on a pdfTeX engine. These are honest scope limits, not bugs; they are listed
   so nobody plans "run pgf's macros" before §3.3 and §3.9 exist.

## 3. The plan — ranked, in landable slices

### 3.1 One node-stream contract — **REWRITE** of the compiler→pipeline boundary (P0)

**What.** The compiler's output becomes the only input to layout. Every fact
the adapter re-derives from `source[span]` (style scopes, interword glue,
quotes/dashes/accents, `\\[skip]`, class options, page breaks, list structure)
is carried by the node stream; floats and `multicols` are parsed by the
compiler (as blocks) instead of masked; `tikzpicture` bodies are lexer-level
verbatim tokens. The adapter shrinks to a pure conversion.

**Why a rewrite.** `rendering-abi.md` §3 asked for exactly this in 2026-09-12
and it has been chipped at feature by feature (`compiler-node-surface`,
`linebreak-skip`, `par-leading`). The remaining re-scan sites are what makes
macro output wrong (#760, #949) and what makes `.sty` execution (S1 of
packages-fonts-manifest, #905) unable to affect layout: a package that
`\renewcommand{\labelitemi}` or `\setlength{\topsep}` is already fine, but one
that defines `\newcommand{\important}[1]{\textbf{\color{red}#1}}` has its
`\textbf` re-derived from the *invocation* bytes. Every future package
executed for real hits this. Extending is not an option: the byte scan cannot
be made macro-aware without becoming a second expander.

**Slices** (each keeps the perf-bench digest gate green or re-records with a
pdflatex diff attached):

1. *Inventory and falsifier tests* (2 days): list every `source[..]`/`text[..]`
   read in `adapter.rs`/`typeset.rs`/`floats.rs`/`multicol.rs`/`fontspec.rs`
   (grep `re-deriv|rescan|source bytes|bytes after`, then the actual slices);
   for each, a test using the #760 trick (`\newcommand` of 2 and 3 bytes) that
   fails today. This is the acceptance list for the rest.
2. *Style and glue on `Inline`* (1 week): `Inline::Text { style, glue_before }`
   as `rendering-abi` §3.1–2 asks, with TeX's space rules resolved in the
   parser (it already has the tokens); delete the adapter's style/gap
   re-scan.
3. *Floats as blocks* (1 week): the compiler parses `figure`/`table`/`*`
   variants into `Block::Float { placement, caption, body }`; `floats::scan` and
   `mask` are deleted; `typeset/floatpage.rs` consumes the block. Same
   digest gate over the 32-case corpus and the float oracles.
4. *`multicols` as a block* (3 days), *tikzpicture as a verbatim token*
   (2 days), *fontspec commands as preamble facts* (2 days).
5. *Split the giants along the new seams*: `adapt_cached` (1,574 LOC),
   `items_from_inlines_styled` (1,144), `build_with_floats` (1,057) — done as
   part of 2–4, not as a separate refactor.

**Dependencies.** §3.2 first (otherwise every slice is also a re-pin). Runs
in parallel with §3.3. Size 4–8 lane-weeks total; Opus/high per slice.

### 3.9 Generic vertical list and `\output` — **REWRITE**, deferred (P0)

**What.** Replace `render-pipeline/src/pagebuild.rs` and the five
feature-specific modules with `crates/page-builder` (already TeX §§967–1028
with inserts, marks and `\vsplit`, oracle-verified, unused) as the single page
model; floats, footnotes, `\marginpar`, `multicols`, `longtable` become
`\insert`/`\mark`/`\output` clients that mirror the real `latex.ltx`/package
code paths rather than transcribe their effects.

**Why a rewrite and why deferred.** The combinations the module headers list
as unrepresentable are exactly the ones a generic model gets for free, and
#944's Tier 0 ("one page per frame including an empty frame") is a page-model
question. But it only pays off once the compiler emits nodes (§3.1) and the
engine can run box code (§3.3); doing it before would mean transcribing the
same features a third time. First slice when its time comes: `pagebuild.rs`'s
callers moved onto `page-builder`'s API with the 32-case digest gate and the
render-pipeline page oracles unchanged, floats and footnotes still their own
modules. 4–6 lane-weeks, Opus/high.
