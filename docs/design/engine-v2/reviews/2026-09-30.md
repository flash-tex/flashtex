## 2. Findings per track

**Track 1, engine** ([report](2026-09-30/track-1-engine.md)):
1. CI does not gate the new engine's parity (above).
2. L3 convergence rarely succeeds on hyperref documents and nothing measures it: full-*
   character edits converge in 8–22/48, sentence insertions 0/18; misses re-typeset to the end
   (full-1000 p95 5.7 s engine time per keystroke, Mac). False negatives by count: link/dest
   whatsits (84), `pdf_char_used` (64), statistics; #1230 adds `intr_state` (10). The rate is
   deterministic across machines, so it is gateable.
3. DESIGN.md mis-states what was built: D8/§5.3 (no running hash; object numbers not
   relocatable), D7 (between-page checkpoints), §4.1 step 2, §8 T0 ("28 directories" → 7),
   §5.6 (a branch result stated as achieved), §9.2 (the PR-tier parity job is the old
   engine's).
4. #1241's unchecked reads trade the no-panic contract for 1–8 %.
5. Stacked, stale PR bases (#1241 on #1230; #1254 on #1247).
6. Hand-copied `pdftex.web` knowledge (≈ 290 constants, hand-proved rules) is the upgrade
   hazard; the change files are not (dry run 1.40.28 → 1.40.29: 1/174 hunks broke).
7. P4 exit-gate items unmeasured or unowned: preamble edit never measured on a quiet host;
   reopen met only pre-warmed; two latency harnesses planned.
8. Effort off the P3–P5 critical path (old-pane tiles, old-engine feature PRs).
9. Duplication worth deleting: the L1-only `host::Session` (~500 lines), `tools/snapshot-bench`
   (5,167), ~2,400 lines of copied evidence scripts.
10. Minor: a foreign `kpsewhich` first on PATH gives a silent INITEX prompt; three host
    sessions died with no stderr captured; lanes share script names on the PC.

**Track 2, app** ([report](2026-09-30/track-2-app.md)):
1. The P5 switch would regress the app with no gate catching it: the v3 pane lacks export
   and print, SyncTeX, zoom, dark preview, VoiceOver text, link clicks, scroll anchoring,
   `.aux` reruns and BibTeX; six rows have no owner.
2. "Keystroke to pixels ≤ 16 ms" is not measurable as written: a commit reaches the screen
   1–2 frames later (commit → next frame p50 11.5–15.4 ms, which fits 120 Hz).
3. The v3 app path costs 1.7–2.9 ms p50; three costs remain: O(n) UTF-8 counting per
   keystroke (hook→sent p95 6.97 ms at 1,000 pages), 12–26 ms of main-thread SwiftUI work per
   keystroke (unowned), and the old worker still compiling with v3 on.
4. Duplicated app lanes (#1228 tiles on the v2 pane vs P3-V3-ZOOM-TILES); §6.2 no longer
   matches the code; four latency harnesses with four definitions.
5. The preview parity gate is weaker than §6.2 states: a 1× floor, integer scales only
   (users see ≈ 2.28 px/pt), smoothing off makes text 25 % lighter than Preview.app.
6. Four IDE features (Find in Project, Rename Citation, Durable History, document kinds)
   never work in the shipped app.
7. CI barely exercises the app's new path; DesignSnapshots gate nothing.
8. Maintainability: `ShellModel` 5,450 lines in 12 files; P5 can retire ≈ 13.2k LOC of Swift.
9. Project semantics: one project per app, no `% !TEX root`, no rerun on `.aux`, no
   BibTeX/biber/makeindex; DESIGN did not say who runs them.

### Owner decisions, with recommendations

1. **O1 · §1.2 keystroke to pixels.** Evidence above. **Recommend:** gate key event
   (`NSEvent.timestamp`) → preview commit (the `CATransaction` that installs the edited page)
   ≤ 16 ms p95, split into host ≤ 11 ms (COMPILE written → edited-page frame read) and app
   ≤ 4 ms; report screen presentation (commit + matched vsync) without gating it.
2. **O2 · Review depth.** Evidence above. **Recommend:** a nightly delta audit (merged PRs
   against the sections they touch, CI truth, new deviations, stale text fixed), a weekly full
   red-team, and full re-research every 2 weeks and at every phase exit, instead of the full
   study nightly.
3. **O3 · P5 gate.** Evidence above. **Recommend:** replace "arXiv L1 ≥ 90 %" with P-T2 ≥ 99 %
   and P-T1 ≥ 98 % of measured documents plus zero panics on the 5k (T4) corpus, add a
   no-TeX-Live gate and an app feature-parity checklist (track 2 §2), and split P5 into
   "flip default" and "retire" with a 14-day soak between them.
4. **O4 · External tools.** **Recommend:** orchestrate the user's TeX Live bibtex, biber and
   makeindex now (adopted i); port `bibtex.web` (through web2rust) and makeindex only for the
   no-TeX-Live bundle case, later.
5. **O5 · Runners on the owner's laptop.** **Recommend:** none; CI runs on the NixOS PC,
   Jaysen's and Daniel's Macs, and GitHub-hosted runners.
6. **O6 · Runner security.** **Recommend (track 5):** every self-hosted runner runs as a
   dedicated standard user with no SSH keys, `gh` login or Claude credentials, and the runner
   group is limited to selected workflows pinned to `main` where the plan allows; where that
   cannot be done, host self-hosted runners only on the PC.
7. **O7 · Multi-window scope.** **Recommend:** P6, not a P5 blocker, but split `ShellModel`
   along the P5 seams now (per-window composition root, track 2 §4.2) so nothing blocks it.
8. **O8 · Pre-warmed host and reopen.** **Recommend:** it does not count; meet "reopen
   ≤ 100 ms" with an app-side persisted page cache shown stale until the host confirms, and
   measure it from the open command (or process start for launch-restore).
9. **O9 · Auto-compile of untrusted projects.** **Recommend:** a project-trust state; the
   first compile of an untrusted project uses `shell_escape=f` (and `openin_any=p`) with a
   "Trust this project" banner that restores stock-pdflatex behaviour, plus a sandbox
   profile for the host later.
