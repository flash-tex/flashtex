# Release checklist: v0.2.0

The owner approved publishing v0.2.0 once **three consecutive complete green
P5 boards** exist. Nothing on this page is done until its box is ticked with a
run ID or SHA. Do not tag or run `release.yml` before every box under "Gate"
is ticked.

- Previous release: `v0.1.9`, published 2026-09-26 (tag commit `bb853342f`).
- Release notes: [`v0.2.0-notes.md`](v0.2.0-notes.md). `release.yml` puts them
  at the top of the published notes. GitHub's list of merged PRs
  (`--generate-notes`) follows them.
- Version: there is nothing to bump by hand. `release.yml` takes the version
  from the tag and passes it on: `make-app.sh --version` sets the app's
  `CFBundleShortVersionString`, and `FLASHTEX_VERSION` sets the CLI's
  `--version`. The smoke step checks that the CLI reports `flashtex 0.2.0 (<sha>)`.
  `make-app.sh`'s local default is now `0.2.0`. Crate versions are not
  release versions and stay as they are.

## Gate: three consecutive complete green P5 boards

A board counts when all of these hold:

- it is a `p5-scoreboard.yml` run on `main` on the **hosted** route (the
  nightly `23 2 * * *` schedule, or
  `gh workflow run p5-scoreboard.yml --ref main -f route=hosted`);
- every job succeeded, including all ten `hosted: T4 shards` jobs (all 50
  shards; `t4_range` left empty and `t4_jobs` at its default; a partial run is never green),
  `P5 scoreboard (new vs v1, every tier; GitHub-hosted)` and
  `P5 scoreboard issues and summary`;
- "consecutive" means no hosted-route run on `main` between them failed.
  A cancelled run is not a green board.

**Commander ruling (kabir-claude, 2026-10-20):** a cancelled or never-started
run neither counts as a board nor breaks the streak. A hosted-route run on
`main` started with `workflow_dispatch` counts the same as a scheduled one.

## Dry run

`release.yml` has no dry-run input: a `workflow_dispatch` run with a version
**publishes** (it creates the tag if it is missing, the GitHub release, and the
website). Checks that publish nothing:

- packaging: `gh workflow run packaging-full.yml --ref main` (hosted macOS;
  builds the app four times, the DMG, bundles and signs the engine host
  ad hoc, launches the app);
- CLI tarball layout: `scripts/tests/package-cli.test.sh` (it runs in CI);
- the notes as published: `cat docs/release/v0.2.0-notes.md`, and then the
  header that `release.yml`'s "Write release notes header" step writes.

## Publish (only after every box above is ticked)

Either of these, never both:

```sh
git tag -a v0.2.0 <release commit> -m "FlashTeX v0.2.0" && git push origin v0.2.0
# or
gh workflow run release.yml --ref <release commit's branch, normally main> -f version=v0.2.0
```

Then:

- [ ] `release.yml` run green: macOS (DMG + CLI, smoke test, `flashtex --version`),
      Linux CLI, publish. Run ID: `________`.
- [ ] The release page lists `FlashTeX.dmg`, `FlashTeX-0.2.0-macos-arm64.dmg`,
      both CLI tarballs and `SHA256SUMS`, and its notes start with these notes.
- [ ] Signing line on the release page: Developer ID + notarized, or the ad-hoc
      warning if the secrets are not set.
- [ ] `site.yml` re-rendered the website for v0.2.0, and the download page and
      `install.sh` point at it.
- [ ] The GPL source line holds: the `v0.2.0` tag is public and its source
      archives are listed on the release.
